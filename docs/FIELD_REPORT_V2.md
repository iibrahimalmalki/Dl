# أمر تطوير: تقرير الجولة الميدانية v2 (FRM-OPS-002)
**المنصة:** دلو ورغوة التشغيلية · **المرجع:** تقرير ميدول حسن 30/09/2026 · **الأولوية:** عالية

---

## 1. الهدف

إعادة بناء مخرج "تقرير الجولة الميدانية" ليصبح ملف PDF احترافياً يُولَّد من الخادم، بغلاف يحمل هوية دلو ورغوة وسويتر، وصفحة قرار واحدة، ثم التفاصيل. **الهوية البصرية الحالية (الألوان، الشعار، أسلوب البطاقات) تبقى كما هي**؛ التغيير في المقاسات، والترتيب، والطباعة، ومنطق العرض.

المشاكل التي يحلها هذا الأمر (مقاسة من الملف الحالي):
- نص المتن 8.4pt والشارات 7.2pt (تحت الحد الأدنى للطباعة).
- الخطوط غير مضمّنة (يطبع بـ Geeza Pro/Helvetica بدل خط المنصة).
- رأس/ذيل المتصفح (رابط vercel + أرقام هندية) يظهر في الملف.
- الصور 280px مقصوصة مربعاً.
- 6 صفحات بفراغ كبير، والخلاصة في الصفحة 5.
- نفس اللون الأحمر لخطأ البايكر ولنقص الإمداد.
- بند يُحسب على البايكر بسبب يخص الإدارة (إعادة دهان الصندوق).

## 2. ثوابت الهوية (لا تُغيَّر)

استخدم هذه القيم كـ CSS variables في قالب الطباعة. كلها مأخوذة من التقرير الحالي:

```css
:root{
  --navy:#0f172a;        /* رأس الصفحة والغلاف */
  --navy-2:#172134;
  --orange:#f79009;      /* شريط النتيجة، عناوين المحاور */
  --orange-deep:#b44708; /* رقم النتيجة، نص التنبيه */
  --orange-soft:#fff7ed; /* خلفية الحكم/التنبيه */
  --green:#12b76a;       /* مطابق */
  --green-soft:#e7f7ef;
  --red:#b42318;         /* غير مطابق (بايكر فقط) */
  --red-soft:#fdecea;
  --amber:#b54708;       /* نقص إمداد (إدارة/سويتر) — جديد */
  --amber-soft:#fdf3e2;
  --blue:#2563eb;        /* أرقام البنود والروابط */
  --blue-soft:#dae6fb;
  --ink:#0f172a; --muted:#64748b;
  --line:#e6e9ed; --surface:#f0f3f5; --surface-2:#f8fafc; --paper:#ffffff;
}
```
- الشعار: أيقونة الدلو البرتقالية داخل مربع أبيض بزوايا 12px على خلفية navy (كما في الرأس الحالي).
- شعار سويتر: يُضاف من ملف SVG رسمي، بارتفاع 60٪ من شعار دلو ورغوة، مع نص "شريك امتياز رقم 47".
- الخط: **IBM Plex Sans Arabic** (أو Tajawal إن كان هو خط المنصة الحالي) — يُضمَّن في الـPDF، لا يُعتمد على خطوط النظام.

## 3. بنية التقرير (5 صفحات كحد أقصى للجولة القياسية)

### الصفحة 1 — الغلاف/القرار (Cover + Executive)
| المنطقة | المحتوى |
|---|---|
| الشريط العلوي (navy، 34mm) | شعار دلو ورغوة يمين، شعار سويتر يسار، اسم التقرير "تقرير الجولة الميدانية" + رمز النموذج FRM-OPS-002 |
| بطاقة البايكر | صورة دائرية 40mm (من ملف التوظيف، بالزي)، الاسم، رقم سويتر، الفريق/المشرف، تاريخ ووقت الجولة، المفتش، الموقع بالاسم (الحي) + إحداثيات صغيرة |
| النتيجة | رقم التزام البايكر 30pt بلون `--orange-deep` داخل مقياس نصف دائري (SVG)، تحته "6 من 8 بنود". بجانبه رقم ثانٍ أصغر: **جاهزية الإمداد** (بنود الإدارة) |
| الحكم | شريط بلون واحد: مطابق (أخضر) / مطابق مع ملاحظات (برتقالي فاتح) / تنبيه رسمي + خطة 7 أيام (برتقالي غامق) |
| الاتجاه | آخر 3 جولات كنقاط متصلة (sparkline) مع النسب، وسهم الفرق |
| الأولويات | حتى 3 أسطر: البند / الإجراء / الموعد |
| الذيل | رقم التقرير (FR-2026-0930-1648)، وقت الإصدار، QR يفتح السجل في المنصة |

### الصفحة 2 — الملخص التحليلي
- جدول المحاور: المحور / البنود / المطابق / النسبة / شريط.
- **السبب الجذري** (جملة واحدة يولّدها التحليل) + **الأثر المالي** وفق HR-POL-003 (ريال الجودة/السلامة) أو "بلا أثر مالي هذه الجولة".
- **خطة التصحيح** جدول: البند / الإجراء / المسؤول / الموعد / طريقة التحقق (صورة/جولة).
- **إجراءات الجولة السابقة**: البند / حالته الآن (أُغلق / مفتوح / **متكرر**). المتكرر يُعلَّم بشارة حمراء.

### الصفحتان 3–4 — البنود بالتفصيل
- لكل محور شريط عنوان بلونه ونسبته.
- كل بند = بطاقة واحدة لا تنكسر بين صفحتين (`break-inside: avoid`):
  رقم البند (أزرق) · العنوان عربي 12pt · الترجمة الإنجليزية 9pt رمادية · شارة الحالة · شارة المسؤولية · صندوق "السبب/الإجراء" بحافة يسرى ملونة · الصور.
- الصور: 3 في الصف، عرض 55mm، نسبة 4:3 بدون قصّ (`object-fit: contain` على خلفية `--surface`)، تعليق سطر + طابع وقت. تُضمَّن بدقة 1200px طولاً (JPEG جودة 80).

### الصفحة 5 — الإغلاق
- **طلب دعم سويتر** جدول: الصنف / الكمية / رقم التذكرة / تاريخ الإرسال / الموعد المتوقع / الحالة.
- **ملخص البايكر بلغته** (بنغالية، 3 أسطر: نتيجته، ما سقط فيه، المطلوب خلال 7 أيام).
- التوقيعات: المفتش / البايكر / المعتمد — كل توقيع مع تاريخ. **المفتش والمعتمد لا يكونان الشخص نفسه** (تحقق في الواجهة).
- سطر "حدود التقرير": الفحص عيّنة في لحظة الجولة.

**يُحذف من الطباعة:** عدّاد "المدة منذ الجولة"، قسم آلية التصعيد بالإيميلات (ينتقل إلى نموذج طلب الدعم فقط)، تكرار "وقت الإصدار".

## 4. مقياس الطباعة (Type Scale)

| العنصر | الحجم | الوزن |
|---|---|---|
| اسم المؤسسة / عنوان الغلاف | 18pt | 800 |
| رقم النتيجة | 30pt | 900 |
| عنوان المحور | 13pt | 800 |
| عنوان البند (عربي) | 12pt | 700 |
| المتن | 11pt | 400 |
| الترجمة الإنجليزية | 9pt | 400، `--muted` |
| الشارات | 9.5pt | 700 |
| التعليقات والحواشي | 8.5pt | 400 |

- لا نص تحت 8.5pt.
- الأرقام غربية (0–9) في كل الملف بما فيه الذيل.
- الاتجاه RTL، والإنجليزية سطر ثانوي فقط تحت عنوان البند؛ **لا ازدواج** في الشارات والتسميات والذيل.
- `@page { size: A4; margin: 14mm 13mm 16mm; }` مع ذيل خاص: "تقرير FR-… · اسم البايكر · صفحة X من Y".

## 5. منطق العرض (تغييرات في البيانات/الحساب)

1. **تقسيم البند 2** إلى: 2أ "الصندوق نظيف" (بايكر) و2ب "حالة الصندوق: دهان/خدوش" (إدارة). أي بند سببه إمداد أو صيانة لا يُحسب على البايكر.
2. **نسبتان مستقلتان**: `biker_score = compliant_biker / assessed_biker`، و`supply_readiness = available_mgmt / assessed_mgmt`. تظهران معاً في الغلاف والملخص.
3. البند غير المقيَّم يظهر "غير مقيَّم — السبب" (مثلاً: لم تُشاهد غسلة كاملة) ولا يُحسب في المقام.
4. الألوان حسب المسؤولية: أحمر = خطأ بايكر، كهرماني = نقص إمداد. أزل أيقونة التحذير المكررة بجانب "الإدارة".
5. الاتجاه يقارن بآخر 3 جولات، ويرفع علم "متكرر" إذا سقط البند نفسه في الجولة السابقة.
6. الحكم النهائي يُحسب من `biker_score` فقط، ويُذكر أثره المالي وفق HR-POL-003 صراحة.
7. "التحليل الذكي" يُخرج: السبب الجذري بجملة، وتوصية واحدة قابلة للتنفيذ بمسؤول وموعد، لا إعادة سرد للأرقام.

## 6. مسار توليد الـPDF (Server-side)

- **الطريقة:** Playwright/Chromium على الخادم (Route: `POST /api/reports/field-round/:id/pdf`).
- القالب: صفحة HTML مستقلة `/print/field-round/:id` (لا تعتمد على واجهة الموبايل)، CSS طباعة مضمَّن، خط مضمَّن `@font-face` (woff2)، `printBackground: true`، `displayHeaderFooter: true` مع قالب ذيل خاص، **بدون** رأس/ذيل المتصفح.
- الصور تُعالج قبل التضمين: إعادة تحجيم إلى 1200px، JPEG q80، تدوير حسب EXIF، ختم وقت الالتقاط في التعليق.
- QR (SVG) لرابط السجل في المنصة.
- التسمية: `FR_<YYYYMMDD>_<sweater_id>_<biker_slug>.pdf`، ويُخزَّن في Supabase Storage تحت `reports/field-rounds/`، ويُسجل رابطه في السجل.
- حد الحجم: ≤ 6MB للتقرير القياسي (14 بنداً، ~20 صورة).
- زر "تصدير PDF" في الواجهة يستدعي الـRoute ويعرض شريط تقدم؛ الطباعة من المتصفح تُعطَّل لهذا التقرير.

## 8. معايير القبول (QA)

- [ ] لا نص في الـPDF أقل من 8.5pt (فحص آلي بـ PyMuPDF على spans).
- [ ] الخط المضمَّن هو خط المنصة في 100٪ من النص (لا Helvetica/Geeza).
- [ ] لا يظهر أي رابط أو رأس/ذيل من المتصفح؛ الذيل مخصص وبأرقام غربية.
- [ ] الغلاف يحتوي: الشعارين، صورة البايكر، الاسم والرقم، التاريخ والوقت، النسبتين، الحكم، الاتجاه، QR.
- [ ] لا بطاقة بند تنكسر بين صفحتين.
- [ ] الصور بلا قصّ، بعرض 55mm، وبتعليق وطابع وقت.
- [ ] أحمر للبايكر فقط، كهرماني لنقص الإمداد.
- [ ] بند إمداد/صيانة لا يخفّض نسبة البايكر (اختبار على تقرير ميدول: النتيجة تصبح 7/8 = 87.5٪ بعد تقسيم البند 2).
- [ ] المفتش ≠ المعتمد (تحقق إلزامي قبل الإصدار).
- [ ] تقرير 14 بنداً ≤ 5 صفحات و≤ 6MB.
- [ ] الملف يُفتح ويُقرأ على iPhone وAndroid والطباعة الورقية A4 بلا تصغير.

## 10. التسليم
1. قالب الطباعة + الـRoute + معالجة الصور.
2. إعادة توليد تقرير ميدول 30/09 بالقالب الجديد كمثال "قبل/بعد".
3. تحديث منطق الحساب (البند 2، النسبتان، غير المقيَّم، التكرار).
4. تقرير QA وفق القائمة أعلاه.

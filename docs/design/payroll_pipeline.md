### ملف `docs/sql/payroll_payments.sql`

**1) الحالات:**
- `status in ('draft', 'approved', 'partially_paid', 'paid')`.
- `update … set status='approved' where status='final'`، بمعاملة تتوقع صفاً واحداً (يونيو).
- **الحالة تُشتق من الأسطر بـtrigger:**
  - كل الأسطر `paid` ⇒ `paid`.
  - بعضها `paid` ⇒ `partially_paid`.
  - السطر المؤجَّل لا يُعدّ مدفوعاً.

**2) أعمدة السطر:**
- `payment_status text default 'pending'`، والقيم: `pending`/`paid`/`deferred`.
- `paid_at date`
- `paid_amount numeric`
- `payment_ref text`
- `bank_fee numeric default 0`: مصروف على المؤسسة، **لا يدخل `total` ولا `net_bonus`**.
- `role` يقبل `adjustment`، مع `reason text`. المبلغ في `net_bonus`/`total`، ويُسمح بالسالب.

**3) RPC `payroll_save(p_run jsonb, p_lines jsonb)` (security definer):**
- يتحقق من `has_perm('payroll', true)` ومن أن المسير `draft`.
- يستبدل الأسطر في معاملة واحدة.
- يعيد id المسير.
- `payroll_approve(p_run uuid)`: للمالك فقط، ويشغّل فحوص §15 داخل القاعدة ثم يعتمد.
- `payroll_pay(p_line uuid, …)`: للمالك فقط، ويسجّل دفع سطر أو تأجيله.
- `payroll_adjust(p_run uuid, p_employee uuid, p_amount, p_reason)`: للمالك فقط. هو **الطريق الوحيد** لتعديل مسير معتمد.

**4) فحوص ما قبل الاعتماد (تمنع الاعتماد):**
